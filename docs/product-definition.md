## 1. 目标用户

### 1.1 角色与优先级

| 优先级 | 角色 | 画像 | 主要任务 | 本版服务程度 |
| --- | --- | --- | --- | --- |
| P0 主用户 | 社内创作成员（作者 / 反馈者） | 动画、摄影、文学等创作型社团的低年级学生；手机为主；作品多为半成品；明确不希望作品被公开检索到 | 投稿、看图、给反馈、查知识、报名活动 | 全链路可用（无通知） |
| P0 主用户（看门人） | 现任社长 / 刚接任的新社长 | 高年级、兼职管理、任期短、换届频繁 | 审批入社、审核帖子与反馈、建活动、发起换届 | 全链路可用（无成员移除） |
| P1 次用户 | 申请人 / 新成员 | 想加入但尚无权限，需要知道社规与进度 | 看公开介绍 → 同意社规 → 申请 → 等结果 | 可用，结果无推送 |
| P2 次用户 | 外社成员 / 游客 | 只应看到社团公开介绍 | 了解社团、决定是否申请 | 只读公开信息 |
| P3 读取方 | 成员自带的只读 Agent（MCP） | 操作者持有本人会话令牌 | 用自然语言查本社团已审核内容与活动 | 只读四工具 |
| 暂不服务 | 公开广场的路人、校方/教师/学工、赞助与商家、跨校用户、匿名交友者 | — | — | 无入口、无角色、无数据 |

### 1.2 为什么是这个顺序

1. 排序依据 = **价值承载 × 不可替代性 × 试点可行性**。
2. **成员第一**：私域内容"不沉底 + 可检索 + 有反馈"的收益只发生在成员身上。若成员不投，社长再高效也没有可审的东西——**供给瓶颈在成员侧**，不在管理侧。
3. **社长第二但不可缺**：社长是唯一能解锁全部能力的角色（审批、审核、建活动、换届）。没有社长，整条链路停摆。排在第二位是因为他的单次动作成本可被压到极低（一次点击），而成员的核心价值无法被替代。
4. **冲突裁决规则**：当社长诉求与成员核心闭环（投稿 → 审核 → 反馈 → 查找）冲突时，默认保成员闭环。管理类便利（批量操作、统计、成员移除）一律排后。
5. **申请人第三**：一次性、低频，但决定入口漏斗，因此其失败路径必须显式（被拒、重复申请、权限未通过时的 403 文案）。
6. **Agent 第四**：是读取便利，不是价值来源；必须复用成员权限，不得成为越权通道。
7. **不服务公开广场的路人是产品立场，不是能力缺失**。私域边界是本版的差异点；任何公开检索入口都会破坏"学生愿意投稿"这一前提假设。

**用户侧假设（未验证）**：成员愿意在"社内可见、需审核"的条件下投稿，社长愿意承担人工审核。原型与产品方案只提供了动机，**没有真实用户访谈数据**。试点前必须补 ≥5 次访谈或等价行为证据（见 §6.3）。

## 2. 核心场景（角色 × 任务）

### S1 入社申请 〔新同学 × 申请〕`[已实现·已验证]`
**主流程**：打开社团公开介绍（不含成员名册与正文）→ 读社规 → 勾选同意 + 填申请理由 → 提交 → `pending` → 社长审批 → `active` 后获得全部私域读取权。

**分支 / 异常**
- 未登录 → 401 `UNAUTHENTICATED`，不落库；
- 未同意社规（`accept_rules` 非 true）/ 理由 <2 字符 / 含多余字段 → 422；
- 重复申请（pending 或 active）→ **不创建第二条**，返回既有状态；被 rejected 后可重新申请 → 回到 pending；
- 申请已被处理时再审 → 409 `ALREADY_REVIEWED`；非社长审批或看名册 → 403 `OWNER_REQUIRED`；
- 网络失败 → 明确报错，**不得显示为"已提交"或空列表**。

### S2 投稿 〔成员 × 发布〕`[已实现·已验证]`
**主流程**：进入发布页即生成 `client_id`（同一次意图重试复用）→ 选类型（作品/知识/提问/闲聊）→ 标题 + 正文 + 可选反馈目标 + 可选单图 → 提交 → `pending` → 在"我的投稿"可见自己的待审内容，其他成员不可见。

**分支 / 异常**
- 同 `client_id` + 相同内容重试 → 返回同一篇，不重复创建；同键换内容 → 409 `INTENT_CONFLICT`（**必须新建发布请求，不能靠换键自动重试未知结果**）；
- 图片非本人 / 非本社团 → 422 `INVALID_MEDIA`；图片已被其他内容占用 → 409 `MEDIA_ATTACHED`；>5 MB → 413；非 PNG/JPEG/WebP 或伪装扩展名 → 422；
- **图片上传与活动创建没有幂等键** → 客户端禁止自动重试，结果不确定时先读现状；
- 非成员投稿 → 403 `MEMBERSHIP_REQUIRED`。

### S3 审核 〔社长 × 审核内容〕`[已实现·已验证]`
**主流程**：社长按 `status=pending` 查看队列 → 通过 / 退回（退回必填理由）→ `approved` 后全社成员可见。

**分支 / 异常**：非社长 → 403；二次审核 → 409 `ALREADY_REVIEWED`；退回无理由 → 422；不存在或跨社团 → 404。
**本版没有原帖编辑与重送审**：退回后按理由另投新稿——**产品文案必须这样写**，不能让作者以为可以修改。

### S4 反馈 〔成员 × 评论〕`[已实现·已验证]`
**主流程**：只能对 `approved` 内容评论 → 评论落 `pending` → 作者与社长可见 → 社长审核 → `approved` 后全体可见。

**分支 / 异常**：对非 approved 内容评论 → 409 `NOT_PUBLISHED`；待审反馈队列仅社长可读（成员 403）；既有审核结果不可被二次覆盖；**评论无幂等键，不得自动重试**。

### S5 知识查找 〔成员 × 检索〕`[已实现·已验证]`
**主流程**：按 `kind=knowledge` 或关键词 `q` 在社内检索 → 默认只返回 `approved`；自己的待审内容用 `mine=true` 查看；社长可用 `status` 查看各审核态。

**边界**：搜索是标题/正文的**字面子串匹配**（`instr`），`%`、`_`、引号不是查询语法；`q` ≤100 字符；分页默认 20、上限 100；**不返回总数，不承诺无限加载**。
**异常**：非成员 → 403；跨社团 `post_id` → 404（不泄露存在性）；客户端**不得发送空的筛选参数**（曾触发 422）。

### S6 活动报名 〔社长 × 创建；成员 × 报名/候补/取消〕`[已实现·已验证]`
**主流程（创建）**：时间必须带时区、开始必须在未来、结束晚于开始、容量 1–1000 整数 → 创建为 `open`。
**主流程（报名）**：open 且未开始 → 未满则 `confirmed`，满则 `waiting` → 取消 confirmed 时按 `(created_at, user_id)` FIFO 递补**仍是有效成员的**候补者。

**分支 / 异常**
- 活动开始后报名/取消 → 409 `REGISTRATION_CLOSED`；活动取消后 → 409 `EVENT_CANCELLED`；
- 并发报名不得超员（容量判定在 `BEGIN IMMEDIATE` 事务内）；
- 重复报名（已 confirmed/waiting）→ 幂等返回原状态，**不改变候补次序**；
- 未报名者取消 → 204 空操作（幂等，可安全重试）；
- 社长取消活动 → 全部报名置 `cancelled`，UI **不得**出现"已确认入场"；
- `waiting` ≠ 入场成功，文案不得写成"报名成功"。

### S7 换届交接 〔社长 × 移交；继任者 × 确认〕`[已实现·已验证]`
**主流程**：现任社长指定**另一位仍是有效成员**的人 → 生成 48 小时有效的 `pending` → 继任者本人登录确认 → 单事务内替换 `owner_id` + 写审计 → 旧社长立即失去管理权。

**分支 / 异常**
- 指定自己 → 422 `INVALID_SUCCESSOR`；指定非有效成员 → 403；非社长发起 → 403；
- 已有 pending：同一继任者 → 返回同一条（幂等）；不同继任者 → 409 `HANDOVER_PENDING`；
- 过期确认 → 409 `HANDOVER_EXPIRED`；期间社长已变更 → 409 `OWNER_CHANGED`；非指定继任者确认 → 403 `SUCCESSOR_REQUIRED`；
- 已完成的同一交接重复确认 → 幂等 200（网络重试友好）。

### S8 只读 Agent 接入 〔成员 × 查询〕`[已实现·已验证 / 真实宿主未验证]`
**主流程**：操作者把**本人**会话令牌配进本机 MCP 宿主 → `initialize`（2025-06-18）→ `tools/list` 只有四个只读工具 → 查询本人社团内容。

**分支 / 异常**：未初始化就调工具 → `-32002`；未知方法 → `-32601`；未知工具或非法参数 → `-32602`；令牌缺失/过期/无权限 → `isError=true` 且带原因，**不得静默返回空数组**；非本机 API 必须 HTTPS；**不跟随重定向**（避免令牌外泄）；响应 >2 MB 报错。
**未验证**：不同 MCP 宿主对 `cwd` 的支持、真实第三方 Agent 的行为。

### S9 权限随时间变化 〔系统 × 一致性〕`[已实现·已验证]`
- 会话 8 小时过期、退出立即删除服务端会话记录 → 旧令牌 401；
- 成员关系被撤销（改为 rejected）后，**既有会话立即失效**（403），不等待令牌过期；
- 换届后旧社长访问管理接口 → 403（不读缓存角色）；
- 每次私域读写都重新校验当前成员关系，不信任前端角色；
- 审核状态不可回退覆盖。

### S10 已知但本版无解的路径（必须写进试点说明）
用户被拒入社 / 投稿被退回 / 候补未递补 / 交接过期——**都没有任何主动通知**，只能靠用户回到页面查看。这是 v0.1 最大的体验缺口。

## 3. 第一版范围

### 3.1 In（交付并验收）

| # | 能力 | 取舍理由 | 不做的代价 |
| --- | --- | --- | --- |
| I1 | 宿主 code 交换 + 可撤销会话（demo 默认关闭） | 权限必须服务端可撤销，退出与换届才有意义 | "换届后旧账号仍掌权"这一核心痛点无解 |
| I2 | 公开介绍 + 同意社规 + 申请 + 社长审批 | 入社留痕是私域边界的前提 | 无法区分成员与外人，所有私域能力失去意义 |
| I3 | 四类内容 + 默认待审 + 退回必填理由 | 小社团没有算法也没有法务，人工审核是唯一可行治理 | 社团承担全部内容风险，学生投稿意愿下降 |
| I4 | 单图（重编码去元数据、读取也鉴权） | 创作型社团的核心载体是图；去元数据是隐私最低要求 | 动画/摄影社团不会用 |
| I5 | 评论（同样待审）+ 反馈目标字段 | 反馈是"作品不沉底"的价值证明 | 只有发布没有反馈，等于另一个云盘 |
| I6 | 私域搜索（标题/正文子串）+ 我的投稿 | 知识沉淀的最小可用形态 | 知识继续沉在群聊里 |
| I7 | 活动 + 容量 + 候补 FIFO + 取消递补 + 活动取消 | 替代群接龙，且接龙没有候补秩序 | 满额后无秩序，成员反复刷群 |
| I8 | 换届双方确认 + 审计 + 旧社长即时失权 | 社团每年换届，管理权交接是结构性痛点 | 毕业账号继续持权，数据无人能管 |
| I9 | 8 页原生双端源码 + 浏览器联调 UI + 移动端布局 | 真实学生在手机上用 | 只有 API 无法验证可用性 |
| I10 | 只读 MCP 四工具 | 让"找知识"可用自然语言完成，且不扩大写入面 | 价值有限，但也不引入风险 |

### 3.2 Out（明确不做，含代价与缓解）

| 项目 | 取舍理由 | 不做的代价（已知并接受） | 缓解 |
| --- | --- | --- | --- |
| 公开广场 / 公开检索 | 立场：私域是本版差异点，公开会让投稿前提失效 | 无自然增长与传播 | 靠社团内线下/群邀请冷启动 |
| 即时聊天 / 完整消息中心 | 群聊已承担沟通，重做 IM 无差异化且拉高治理成本 | **审核结果、递补、过期都不主动通知** | 打开页面即见状态 + 线下公告；列为最大体验缺口 |
| 支付 / 学分 / 签到 / 现场核销 | 涉及资金与学籍，合规成本远超收益 | 到场无法核验 | 线下人工点名 |
| 点赞 / 收藏 / 视频 / 知识版本 / 原帖编辑重送审 | 需先有内容量才有意义；编辑重送审会打乱审核状态机 | 作者改错字只能另投 | 文案明示"退回后另投新稿" |
| 举报 / 申诉 / 版权 / 移除成员 | 需要运营主体与人工通道，不是代码问题 | **无法处理恶意成员与侵权内容** | 仅限虚构数据演示；列为真实试点硬门禁 |
| 跨平台账号绑定 | 以 `(provider, subject)` 为唯一账号；按昵称合并身份会造成越权 | 同一人微信/QQ 是两个账号 | 试点单端 |
| 邀请深链 / 匿名交友 / 公开展览 / 插件框架 / 多实例 | 无验证过的需求；SQLite 单实例是本版前提假设 | 冷启动与扩容受限 | 负载数据出现缺口后再评估 |
| 任何假按钮 | 立场：不在 UI 放不可用入口 | — | 原型中未产品化的页面直接不出现 |

### 3.3 已知缺口（不是新功能，但工程与测试必须知道）

- **G1 无成员移除**：换届是唯一权限收回路径；恶意成员只能线下处理。
- **G2 无通知**：审核、递补、交接过期都要用户主动回来看。
- **G3 搜索是子串匹配**：承诺上限是"找得到你记得的那个词"，不是分词与模糊检索。
- **G4 无退社**：membership 只有 pending/active/rejected，成员无法自行离开。
- **G5 帖子审核无独立队列页**：社长用 `status=pending` 列表；评论有独立队列接口。
- **G6 三处无幂等键**：评论、图片上传、活动创建——客户端不得自动重试。
- **G7 审核为纯人工**：不声称已接入平台文本/图片安全服务。

## 4. 暂缓事项排期

### 轨道 A：试点门禁（真实学生使用前必须，非产品功能）

| # | 事项 | 依赖前提 | 阻塞什么 |
| --- | --- | --- | --- |
| A1 | 运营主体 / 学校授权 / 平台类目资质 | 人力与法务决策 | 一切真实用户 |
| A2 | 微信/QQ AppID、合法域名、隐私声明、真机验证 | A1 | 真实 code 登录 |
| A3 | HTTPS + 入口限流 + 请求体限制（建议 8 MB）+ 备份恢复演练 | 部署环境 | 对外开放 |
| A4 | 数据治理：最少收集、保留期限、导出与删除路径 | A1 | 合规上线 |
| A5 | 内容治理：举报、申诉、禁用成员、应急响应 | 运营人手 | 开放真实发布 |
| A6 | 依赖漏洞扫描、密钥管理、日志脱敏 | CI 可联网 | 安全评审 |

### 轨道 B：v0.2 候选（按优先级，试点前可选，试点中最先被要求）

| 顺序 | 事项 | 依赖前提 | 触发条件 |
| --- | --- | --- | --- |
| B1 | 内容治理最小闭环：举报 + 移除成员 + 禁用发布 | A5 | 任何真实内容风险事件，或试点校要求 |
| B2 | 审核/递补/过期结果通知（平台订阅消息） | A2 | >30% 待审内容 48h 未被审核，或成员反馈"不知道要回来看" |
| B3 | 三处写接口补幂等键（评论、图片、活动） | 无 | 出现一次重复评论或重复活动即可做（成本低） |
| B4 | 成员自助退社 | B1（需与移除语义对齐） | 成员要求离开，或数据删除义务倒逼 |
| B5 | 原帖编辑重送审 | 审核状态机扩展设计 | 退回率 >20% 且原因多为笔误 |
| B6 | 试点数据看板（审核时长、投稿→反馈转化、候补转化、留存） | 埋点方案 | 试点启动前必须补齐，否则 §6.4 无法度量 |

### 轨道 C：试点后按数据决定

| 事项 | 触发条件 |
| --- | --- |
| 通知中心 / 站内信 | B2 不足以覆盖 |
| 逐篇"公开作品"开关 | 有社团明确要求对外展示，且 B1 已就绪；**会改变私域前提，需重新评估定位** |
| PostgreSQL / 对象存储 | 图片库 >2 GB，或并发写冲突成为可观测瓶颈 |
| 点赞 / 收藏 / 视频 / 知识版本 | 单社团 approved 内容 >200 篇后仍被要求 |
| 跨端账号绑定 | 同一自然人双端使用成为高频投诉 |

### 轨道 D：更远 / 不做
支付、学分、匿名交友、公开展览、多租户 SaaS、插件框架。

## 5. 验收标准（AC）

> 每条含边界与反向验证；`→` 后为反向或边界断言。测试名指向现有证据。

### 5.1 身份与会话

- **AC-ID-01** `[已验证 test_demo_is_off_by_default]` Given 未显式开启 demo 的实例，When 请求 `POST /auth/demo` 任意 persona，Then 404 且不签发会话。→ 显式 `demo=true` 时同一请求 200 并返回令牌。
- **AC-ID-02** `[已验证 test_production_rejects_demo / test_production_refuses_an_existing_demo_database / test_demo_refuses_an_existing_real_database]` Given production 模式，When 以 demo 启动、对 demo 库以生产打开、或对真实库开启 demo，Then 启动失败且不进入服务态。
- **AC-ID-03** `[已验证 test_private_detail_requires_login]` Given 无 `Authorization` 头，When 请求任何私域资源（`/me`、帖子、活动、图片、名册），Then 401 `UNAUTHENTICATED` 且响应体不含任何业务数据。→ 公开社团接口此时仍应 200。
- **AC-ID-04** `[已验证 test_expired_session_is_rejected]` Given 会话已过期（8h），When 用旧令牌请求，Then 401。→ 把 `expires_at` 改回未来即恢复 200，证明过期判定来自服务端时间而非客户端。
- **AC-ID-05** `[已验证 test_logout_revokes_session]` Given 已登录，When `DELETE /auth/session`，Then 204 且同一令牌再用返回 401。
- **AC-ID-06** `[已验证 test_provider_identity_is_scoped_and_sessions_are_hashed]` Given 同一 subject 来自 wechat 与 qq，When 登录，Then 生成两个不同 user；`sessions` 表按令牌摘要存储。→ 用明文令牌查库应查不到记录。
- **AC-ID-07** `[已验证 test_malformed_provider_response_fails_closed / test_real_login_never_falls_back_to_demo]` Given 宿主返回畸形或错误响应（空数组、缺 openid、`errcode≠0`、含 `session_key`），When 登录，Then 401 `PROVIDER_REJECTED`，**不回退 demo**，错误体不含 app secret。→ 凭据未配置时返回 503 `PROVIDER_NOT_CONFIGURED`，不得降级为 demo 或成功。
- **AC-ID-08** `[已验证 test_profile_never_exposes_provider_subject / test_public_responses_do_not_expose_owner_ids_or_internal_intents]` Given 任意响应，When 序列化，Then 不含 `subject`/`session_key`；公开社团不含 `owner_id`；帖子不含 `client_id`。
- **AC-ID-09** `[未验证]` 真实微信/QQ code 交换、授权弹窗、真机与基础库兼容。→ **未取得真机证据前，任何文档与界面不得写"已支持微信登录"。**

### 5.2 入社与权限

- **AC-MEM-01** `[已验证]` 申请必须满足 `reason` 2–500 字符且 `accept_rules` 为布尔真，否则 422。→ 提交 `role`/`owner_id`/`openid` 等未知字段一律 422，且**不会因此获得任何权限**。
- **AC-MEM-02** `[已验证 test_join_requires_review_and_rules_consent]` Given 已申请且状态为 pending/active，When 再次申请，Then 不新增记录并返回既有状态。→ 被 rejected 后重新申请，状态回到 pending 而非直接 active。
- **AC-MEM-03** `[已验证]` Given 申请为 pending，When 社长 `PATCH` 为 active/rejected，Then 状态变更并写审计。→ 二次审批 409 `ALREADY_REVIEWED`；非社长 403 `OWNER_REQUIRED`。
- **AC-MEM-04** `[已验证 test_member_cannot_approve_or_enumerate_roster]` Given 普通成员，When 读成员名册或审批他人，Then 403。→ 社长同一请求 200，且只返回本社团成员。
- **AC-MEM-05** `[已验证 test_outsider_cannot_read_private_resources]` Given 非成员（游客、外社成员、仅申请人），When 请求帖子列表/详情/搜索/活动/名册/图片，Then 403 或 404。→ **不得返回 200 + 空列表冒充"没有内容"**。
- **AC-MEM-06** `[已验证 test_join_requires_review_and_rules_consent]` Given 申请处于 pending，When 读取私域内容，Then 403；社长审批为 active 后同一会话同一请求变 200（**登录 ≠ 入社**）。

### 5.3 私域隔离

- **AC-PRIV-01** `[已验证 test_pending_post_hidden_until_approval]` Given 一篇 pending 帖子，When 其他成员读详情或列表，Then 404 / 不出现；作者本人 200 且 `status=pending`；社长 200。→ 待审内容不得出现在任何列表、搜索结果、MCP 结果中。
- **AC-PRIV-02** `[已验证]` Given 列表请求，When 默认查询，Then 只返回 approved；`mine=true` 返回本人全部状态；`status=` 非空时仅社长可用。→ 普通成员带 `status` → 403。
- **AC-PRIV-03** `[已验证 test_search_scoped_and_paginated]` Given 关键词 `q`，When 检索，Then 仅在本社团内按标题/正文子串匹配且仅 approved。→ 输入 `%` 或 `_` 按字面处理，不得返回全量；`limit=99999` → 422；结果不得出现其他社团内容。
- **AC-PRIV-04** `[已验证 test_media_is_private_before_and_after_publication]` Given 图片 id，When 未登录 → 401；非成员 → 403；成员访问**未关联帖子**的他人图片 → 404；成员访问已发布可见帖子的图片 → 200 且 `content-type: image/png`。→ 媒体不在静态目录，不存在可绕过的公开 URL。
- **AC-PRIV-05** `[已验证 test_media_cannot_be_stolen_from_another_author]` Given 他人上传的 `media_id`，When 关联到自己的帖子，Then 422 `INVALID_MEDIA`；重复使用已关联图片 → 409 `MEDIA_ATTACHED`。
- **AC-PRIV-06** `[已验证 test_outsider_cannot_read_private_resources]` 跨社团访问一律 403/404，且 **404 优先于暴露存在性**（用别社团的 `post_id` 不得区分"不存在"与"无权限"）。

### 5.4 内容与审核

- **AC-CONTENT-01** `[已验证 test_post_validates_at_boundary]` 边界：`title` 1–100、`body` 1–10000、`feedback` ≤500、`client_id` 1–80、`kind ∈ {work,knowledge,question,chat}`。→ 越界或非法值 422 `VALIDATION_ERROR` **且不落库**（用同 `client_id` 查询应无记录）；客户端提交 `status:"approved"` 不得生效。
- **AC-CONTENT-02** `[已验证 test_post_idempotency_does_not_duplicate_and_rejects_changed_payload]` Given 同 `client_id` + 同内容，When 重复提交，Then 返回同一 `id` 不重复创建。→ 同键换内容 409 `INTENT_CONFLICT`。
- **AC-CONTENT-03** `[已验证 test_reject_requires_reason_and_cannot_review_twice]` 新帖默认 `pending`；退回必须带 `reason`（否则 422）；已处理内容二次审核 409。→ `approved` 后不得被改判为 `rejected`。
- **AC-CONTENT-04** `[已验证 test_comment_requires_review]` 评论只能写在 approved 帖子上（否则 409 `NOT_PUBLISHED`），默认 `pending`，仅作者与社长可见；审核通过后全体可见。
- **AC-CONTENT-05** `[已验证]` 待审反馈队列仅社长可读且只含 pending（成员 403）。→ 队列不得包含已处理的反馈。
- **AC-CONTENT-06** `[已验证（结构性）]` 全部状态变更（申请、审批、投稿、审核、活动、报名、交接）写审计（actor、club、action、target、时间）。→ 审计不得保存正文副本或密钥。
- **AC-CONTENT-07** `[未实现·本版不做]` 原帖编辑/重送审、知识版本、点赞收藏、举报申诉。→ 不得在 UI 预留入口或返回占位成功。

### 5.5 图片

- **AC-MEDIA-01** `[已验证 test_rejects_svg_disguised_as_image]` >5 MB → 413 `IMAGE_TOO_LARGE`；非 PNG/JPEG/WebP 或伪装扩展名 → 422 `INVALID_IMAGE`；>16M 像素 → 422。→ 上传文本文件伪装成 `image/png` 必须 422，不得按扩展名放行。
- **AC-MEDIA-02** `[已实现·已验证（间接）]` 成功图片统一解码后重编码为 PNG、清除元数据、长边缩至 2400。→ 输出中不得残留原 EXIF（需补一条显式断言）。
- **AC-MEDIA-03** `[未实现·试点门禁]` 入口侧 multipart 体积限制（建议 8 MB）。→ 服务层 5 MB 检查**不能替代**入口流量与临时磁盘限制；未配置前不得开放真实上传。

### 5.6 活动容量与递补

- **AC-EVENT-01** `[已验证 test_member_cannot_publish_events]` 仅社长可创建与取消活动。→ 成员创建 403，成员取消 403。
- **AC-EVENT-02** `[已验证 test_event_rejects_invalid_time_or_capacity]` 时间必须带时区、开始在未来、结束晚于开始、容量为 1–1000 严格整数。→ 无时区时间 422（**不得默认成 UTC**）；`capacity=0`、`capacity="2"` 均 422。
- **AC-EVENT-03** `[已验证 test_full_event_waitlists_and_promotes_on_cancellation]` Given 容量 N 且 confirmed 已满，When 第 N+1 人报名，Then `waiting` 且 confirmed 计数不变。→ 一名 confirmed 取消后，最早 `(created_at, user_id)` 且仍为 active 成员的候补者转 confirmed 并写审计；若候补者已被移出社团则不递补给他。
- **AC-EVENT-04** `[已验证 test_concurrent_registration_never_exceeds_capacity]` Given 并发请求数 > 容量，When 全部完成，Then confirmed 数恒 ≤ 容量且无重复报名行。→ 断言最终 confirmed **等于**容量（既不能超，也不能因竞争丢座）。
- **AC-EVENT-05** `[已验证 test_full_event_waitlists_and_promotes_on_cancellation]` 重复报名（已 confirmed/waiting）幂等返回原状态。→ 重复提交不得刷新 `created_at`（不能靠重刷抢候补顺序）。
- **AC-EVENT-06** `[已实现·已验证（部分）]` 取消自己的报名：仅 confirmed 取消触发递补；waiting 取消不递补；未报名者取消 → 204 空操作（幂等可重试）。
- **AC-EVENT-07** `[已验证 test_full_event_waitlists_and_promotes_on_cancellation]` 活动开始后报名/取消 → 409 `REGISTRATION_CLOSED`；活动取消后报名 → 409 `EVENT_CANCELLED`。→ 未报名者的取消空操作不受此限制。
- **AC-EVENT-08** `[已验证]` 社长取消活动 → 活动 `cancelled` 且所有报名置 `cancelled`。→ 任何成员再查该活动，`my_registration` 不得为 `confirmed`；UI 不得显示"已确认入场"。

### 5.7 换届交接

- **AC-GOV-01** `[已验证 test_handover_requires_two_people_and_revokes_old_owner]` Given 现任社长指定另一位有效成员，Then 创建 48 小时有效的 pending。→ 继任者确认前 `owner_id` 不变：旧社长仍可管理，继任者不可管理。
- **AC-GOV-02** `[已验证]` 指定自己 → 422 `INVALID_SUCCESSOR`；指定非 active 成员 → 403；非社长发起 → 403。
- **AC-GOV-03** `[已实现·已验证（部分）]` 已有 pending 时：同一继任者重复发起 → 返回同一条；不同继任者 → 409 `HANDOVER_PENDING`。→ 过期 pending 在下次发起时被标记 expired。
- **AC-GOV-04** `[已实现·已验证（部分）]` 非指定继任者确认 → 403 `SUCCESSOR_REQUIRED`；>48 小时确认 → 409 `HANDOVER_EXPIRED`；期间社长已变更 → 409 `OWNER_CHANGED`。
- **AC-GOV-05** `[已验证]` Given 继任者本人确认，Then 单事务内替换 `clubs.owner_id`、handover 置 `completed`、写审计。→ 任一步失败时二者必须同时保持原值（不得出现"人换了但记录还是 pending"或反之）。
- **AC-GOV-06** `[已验证 test_handover_requires_two_people_and_revokes_old_owner / test_revocation_applies_to_existing_session]` 交接完成后旧社长的**既有会话**立即失去全部管理权限（名册、审批、审核、建活动、再发起交接 → 403），新社长无需重新登录即可管理。→ 成员资格被撤销时同样立即失效。

### 5.8 MCP 只读边界

- **AC-MCP-01** `[已验证 test_initialize_declares_only_read_tools]` `initialize` 返回 `protocolVersion=2025-06-18`；`tools/list` 恰为 `list_clubs/list_posts/get_post/list_events` 且 `readOnlyHint=true`。→ 不存在任何写工具、管理员工具或万能令牌。
- **AC-MCP-02** `[已验证 test_tool_arguments_cannot_inject_path_or_override_token]` 参数仅限 `club_id/post_id/kind/q/limit/offset`，id 必须匹配 `^[A-Za-z0-9_-]{1,80}$`。→ 无法覆盖令牌、无法指定任意 URL、无法路径穿越；非法参数 → `-32602`。
- **AC-MCP-03** `[已验证 test_missing_token_is_visible_tool_error]` Given 令牌缺失/过期/无权限，When 调用工具，Then `result.isError=true` 且文本说明原因。→ **不得返回空 `items` 数组冒充"没有内容"**。
- **AC-MCP-04** `[已验证 test_real_mcp_uses_caller_membership]` Given 成员令牌 → 可读本社团已审核内容；Given 非成员令牌 → `isError=true`。→ MCP 不直连数据库，其可见范围与 HTTP API 完全一致（同社团、同审核态、同分页上限）。
- **AC-MCP-05** `[已验证 test_stdio_is_newline_json_without_debug_stdout / test_unknown_method_and_invalid_tool_have_protocol_errors]` stdout 每行一条 JSON-RPC，诊断走 stderr；未初始化即调用工具 → `-32002`；未知方法 → `-32601`。→ 单行 >1 MB 时报 `-32600` 而不是执行片段。
- **AC-MCP-06** `[已验证 test_tool_arguments_cannot_inject_path_or_override_token]` 非本机 API 必须 HTTPS；不跟随重定向；响应 >2 MB 报错。→ 协议为自实现，**不得宣称完整 MCP 兼容认证**。

### 5.9 系统语义与客户端

- **AC-SYS-01** `[已验证]` 所有错误形如 `{error:{code,message}}`，覆盖 401/403/404/409/413/422/500/503；未知输入字段一律 422；校验错误不回显请求体、登录 code 或密钥。
- **AC-SYS-02** `[已实现·部分验证]` 网络失败与超时不得返回伪成功或空列表，前端必须显示可见错误态。→ 需为离线/超时补一条确定性测试（当前靠 e2e 与代码审查）。
- **AC-SYS-03** `[已验证（代码）]` 每个响应带 `Cache-Control: no-store` 与基础安全头；列表返回 `{items,limit,offset}`，默认 20、上限 100。→ 不承诺总数与无限滚动；部分页面显式限制前 100 条。
- **AC-SYS-04** `[已验证 e2e + 远端 CI run 35576212147]` 端到端链路（浏览器 UI + 真实临时 HTTP API）：成员登录 → 筛选 → 单图投稿 → 待审 → 社长审核 → 他人反馈 → 反馈审核 → 申请入社 → 审批 → 报名并取消 → 换届 → 旧社长失去管理入口。→ 全程零 JavaScript 运行时错误，`<script>` 以文本显示；本地扩展后该脚本共 33 项检查（原 15 项 + 18 项布局检查）。
- **AC-SYS-05** `[已验证 e2e 33 项（本地）]` **10 个页面路由**（动态、社团目录、发布、作品详情、我的投稿、活动列表、活动详情、账号与交接、社长工作台、发起活动）在 320 / 390 px 无横向溢出；动态页另测 768 / 1440 px。→ **不得**据此声称无障碍合规，也不得用相同结论覆盖未测试的新页面；新增页面必须补测。
- **AC-SYS-06** `[已验证]` 重启后已提交数据保留；备份通过完整性检查。→ 备份不得覆盖已存在文件；**不得**用"回退 Git 提交"代替数据回滚。

## 6. 完成定义与停止条件

### 6.1 单个迭代 DoD
1. 相关测试先红后绿；无 skip 的失败测试，无假 benchmark 数字；
2. 每条 AC 至少有一个**反向或边界断言**，不得只测 happy path；
3. 接口变更同步 `docs/api.md` 与契约模型；
4. 路由层不出现 SQL，`db.py` 不出现业务策略；
5. 错误路径有可观察证据（状态码 / 错误码 / 前端错误态），网络失败不得被吞掉。

### 6.2 版本 DoD（可判"v0.1 完成"）
1. §5 中全部 `[已实现·已验证]` 的 AC 在 CI 全绿（当前证据：58 passed；e2e 33 项，其中布局检查为本地运行；MCP live 通过；远端 CI `c63ce46` 尚未包含本次扩展）；
2. §3.1 的 In 列表逐条有对应实现，无缺项；
3. §3.2 的 Out 项在 UI 与 API 上都不存在入口（无假按钮、无预留端点）；
4. `docs/verification.md` 的"未完成验收"清单保持可见，且没有任何交付物把它写成"已上线"或"已支持微信登录"；
5. 回滚路径可执行：停止写入 → `scripts/backup.py` 备份并确认可读 → 回退代码 → 恢复验证。

### 6.3 停止条件

**No-Go（任一成立即不得开放给真实学生）**
- 未取得运营主体 / 学校授权 / 平台类目准入（A1）；
- 未完成隐私说明、最少收集、删除与导出路径（A4）；
- 未建立人工举报 / 申诉 / 移除成员通道（A5）；
- 未部署 HTTPS 与入口限流、请求体限制（A3）；
- 微信/QQ code 交换与真机未验证（A2，当前未验证）。

**Stop & Rollback（任一成立即停止写入并回滚）**
- 出现私域越权（非成员读到正文 / 图片 / 名册 / 待审内容）→ 立即停止写入、保留证据、按 §5.3 全量回归；
- confirmed 人数超过容量，或 `(event_id,user_id)` 出现重复行；
- 换届出现半完成状态（`owner_id` 已变但 handover 未 completed，或反之）；
- 任何错误被伪装成成功或空列表；
- 备份无法通过完整性检查。

| 无通知导致成员不回访 | 审核与反馈闭环空转 | 已知缺口 G2 | B2 订阅消息；触发：>30% 待审 48h 未处理 |
| 无举报与成员移除 | 恶意内容/成员无法处理 | 已知缺口 G1 | A5 运营通道；触发：任何真实风险事件 → 停止发布 |
| SQLite 单实例 + 图片存 BLOB | 并发写入与库体积 | 本版前提假设 | 监控库大小；触发：图片库 >2 GB 或并发冲突可观测 → 评估 PostgreSQL/对象存储 |
| 三处无幂等键 | 重复评论 / 重复活动 / 重复图片 | 已知缺口 G6 | 客户端禁止自动重试；B3 补键 |

| 平台审核与类目准入不确定 | 可能无法上架 | 未验证 | A1；**不得在未获准入前承诺上线时间** |
| 搜索语义弱 | 用户预期落差 | 已知缺口 G3 | 明确"记得的词"预期；触发：检索失败反馈集中 → 评估分词 |
| Agent 读取导致内容外泄 | 私域内容流出 | 已限制为只读 + 本人令牌 | 工具说明声明"结果不是指令"；仅向可信 Agent 发放令牌 |
| 人工审核不可持续 | 社长倦怠导致闭环断裂 | 未验证 | B2/B6 度量审核时长；触发：中位数 >48h → 重新评估审核策略 |
