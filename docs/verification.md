## 浏览器实际操作链

成员登录 → 切换作品/全部筛选 → 查看私域动态 → 单图投稿 → 待审状态 → 社长审核 → 另一成员查看并反馈 → 社长审核反馈 → 新同学同意社规并申请 → 社长审批 → 报名并取消活动 → 社长指定继任者 → 继任者确认 → 原社长无法继续访问管理页。

同一测试检查 `<script>` 字样以文本显示、私域图片以鉴权请求加载、四个屏幕宽度布局、零 JavaScript 运行时错误。API 测试另覆盖重复投稿意图冲突、候补与并发不超员、图片归属、会话过期和跨社团访问。

`artifacts/e2e.json`、截图和本地服务日志由脚本生成，默认不进 Git；随交付压缩包提供，CI 也会保留自己的运行产物。只有虚构数据日志，日志不包含会话令牌。

## 实际遇到并解决的问题

- 初始 API 骨架的私域测试预期 401、实际 404，补齐身份与成员规则后通过。
- 浏览器环境禁止 URL 导航，因此原生 HTTP 浏览器测试被阻止。没有修改浏览器策略；改为显式 `--bridge` 测试模式。受限环境不能据此声称网络链路已验收。
- 离线浏览器上下文没有 `crypto.randomUUID`。发布意图改为使用 `crypto.getRandomValues` 创建，并保留同一请求的重试键。
- “全部”筛选曾发送空 kind，触发 422；先用浏览器回归复现，随后删除空参数，完整 15 项交互检查重新通过。
- 增加独立响应模型，公开社团不再返回 owner_id，帖子不返回内部 client_id。
